# API для игры

Этот файл описывает ту часть проекта, которую удобно использовать на уроках.
Низкоуровневые функции Pico, дисплея и C++ модуля детям трогать не нужно.

## Главная идея

Любая игра состоит из трех частей:

```text
Game    обновляет игру и рисует кадр
Actor   хранит игровой объект: игрока, подарок, врага, монету
keys    хранит нажатые кнопки
```

В игре типа Terraria еще есть `World`, который хранит блоки мира.
В игре “поймай подарок” мира из блоков может вообще не быть.

## Игровой объект Actor

`Actor` подходит для игрока, подарка, врага, пули или монеты:

```python
from api import Actor, GREEN, RED

player = Actor(60, 100, 20, 6, GREEN)
gift = Actor(20, 0, 8, 8, RED)
```

У объекта есть координаты, размер и скорость:

```python
player.x
player.y
player.w
player.h
player.vx
player.vy
```

Чтобы объект сдвинулся по скорости:

```python
player.move()
```

Чтобы объект не вышел за экран:

```python
player.keep_inside(160, 120)
```

Чтобы проверить столкновение:

```python
if player.overlaps(gift):
    score += 1
```

Чтобы нарисовать объект прямоугольником:

```python
player.draw(gfx)
```

## Ввод

В `update(keys)` доступны кнопки:

```python
keys.left
keys.right
keys.jump
keys.dig
keys.place
keys.aim_x
keys.aim_y
```

На компьютере это клавиатура и мышь.
На Pico это джойстик и кнопка.

`aim_x` и `aim_y` показывают отклонение джойстика для выбора блока:

```text
-100  сильно влево или вверх
   0  центр
 100  сильно вправо или вниз
```

В текущей игре физический джойстик на Pico временно выбирает блок для копания,
а движение идет через `tools/keyboard_to_pico.py`.
Выбранный блок подсвечивается желтой рамкой, но пока не ломается.
Зона выбора прямоугольная: до трех блоков от тела игрока по горизонтали
и вертикали.
Выбор блока настроен ступенчато и рассчитан на небольшие отклонения:
малое отклонение выбирает ближний блок, среднее - блок подальше,
уверенное - самый дальний доступный блок.
Если курсор попадает в клетки самого игрока, рамка не рисуется.

Для меню можно использовать общее действие:

```python
if keys.action:
    start_game()
```

Временный режим разработки для Pico:

```bash
python3 tools/keyboard_to_pico.py
```

Он отправляет стрелки с компьютера на Pico по USB.
Это временный мост, пока не подключен второй джойстик.
Когда появится нормальное железо, можно удалить `tools/keyboard_to_pico.py` и
выключить `KEYBOARD_BRIDGE_ENABLED` в `backends/pico_backend.py`.

Текст рисуется маленьким пиксельным шрифтом:

```python
gfx.text(56, 48, "START", WHITE, scale=2)
```

Поддерживаются английские заглавные буквы, которые нужны для интерфейса игры.

Один блок мира имеет размер `8x8` игровых пикселей.
На экране Pico он показывается крупнее, потому что движок масштабирует картинку.

## Блоки мира

Этот раздел нужен для игр с миром из блоков.
Для игры “поймай подарок” его можно пропустить.

Используй блоки из `api`:

```python
from api import BLOCK_AIR, BLOCK_DIRT, BLOCK_STONE
```

Значения:

```text
BLOCK_AIR    пустота
BLOCK_DIRT   земля
BLOCK_STONE  камень
```

Важный момент: отдельного блока “трава” нет.
Трава появляется при рисовании, если над землей пусто.

```python
if world.get(x, y - 1) == BLOCK_AIR:
    # земля будет выглядеть как земля с травой
```

## Генерация мира

Мир создается один раз при запуске в `game_core/world.py`.
Текущий генератор делает:

```text
1. поверхность с холмами
2. слой земли разной толщины
3. камень в глубине
4. небольшие пещеры
5. безопасное место появления игрока
```

Генератор детерминированный:

```python
world = World(seed=7)
```

Одинаковый `seed` дает одинаковый мир.
Это удобно, когда нужно повторить баг или показать всем детям один и тот же уровень.

Блоки мира хранятся компактно в `bytearray`.
Один блок занимает один байт.
В игре по-прежнему используются обычные методы:

```python
world.get(x, y)
world.set(x, y, block)
```

Можно посмотреть, сколько байт занимает карта блоков:

```python
print(world.memory_bytes())
```

Например, мир `200x50` занимает:

```text
200 * 50 = 10000 байт
```

Для Pico это нормально и быстрее, чем чанки на MicroPython.
Чанки можно будет вернуть позже, если мир станет намного больше.

## Движение игрока

У игрока есть координаты и скорость:

```python
player.x
player.y
player.vx
player.vy
```

`x` и `y` измеряются в игровых пикселях, не в блоках.

Направление игрока:

```python
player.facing
```

```text
-1  смотрит влево
 1  смотрит вправо
```

Состояние игрока:

```python
player.state
```

```text
SpriteState.IDLE  стоит
SpriteState.WALK  идет
SpriteState.JUMP  прыгает или падает
```

## Простая анимация

Для анимации есть класс `Animation`:

```python
from api import Animation

walk = Animation(["walk1", "walk2"], frame_ms=120)
frame = walk.frame(time_ms)
```

Он выбирает кадр по времени.
Например, если прошло достаточно времени, `walk1` сменится на `walk2`.

Такой же подход работает не только для игрока:

```python
coin = Animation(["coin1", "coin2", "coin3"], frame_ms=80)
gift_frame = coin.frame(time_ms)
```

Пока игра использует один hi-res спрайт игрока `player_default`.

## Спрайты и текстуры

Редактор спрайтов сохраняет картинки в `assets/sprites` и обновляет
`assets/sprites/manifest.json`.

Маленькие спрайты `8x8` загружаются по manifest автоматически:

```text
tile   блоки мира: dirt, grass, stone
item   предметы интерфейса: heart
enemy  маленькие враги
free   свободные 8x8 картинки
```

В коде игры лучше обращаться к ним по имени через API, а не запоминать числа:

```python
from api import sprite8_id

stone = sprite8_id("tile", "stone")
heart = sprite8_id("item", "heart")
```

После добавления нового `8x8` тайла или предмета обычно не нужна новая
прошивка `firmware.uf2`. Достаточно сохранить спрайт в редакторе и загрузить
файлы на Pico:

```bash
python3 tools/upload_to_pico.py
```

Ограничение движка сейчас: до `32` маленьких спрайтов `8x8`.
Если когда-нибудь понадобится больше, тогда надо будет один раз увеличить
лимит в C++ и пересобрать прошивку.
Следующий шаг для анимации игрока - загрузить несколько спрайтов:

```text
player_idle.bin
player_walk1.bin
player_walk2.bin
player_jump.bin
```

А затем выбирать нужный по `player.state`.

## Тайлы

Тайлы земли лежат тут:

```text
assets/sprites/tiles/dirt.bin
assets/sprites/tiles/grass.bin
```

В коде игры не нужно помнить их номера.
Для этого есть функция:

```python
from api import dirt_tile

tile_id = dirt_tile(has_air_above=True)
```

Если сверху воздух, вернется тайл земли с травой.
Если сверху не воздух, вернется обычная земля.

## HUD и маленькие спрайты

Для интерфейса можно рисовать маленькие спрайты `8x8`.
Например, сердечки здоровья:

```python
from api import SPRITE_HEART

gfx.sprite8(120, 2, SPRITE_HEART)
```

В текущей игре пять сердечек рисуются справа сверху.
Одно полное сердце равно `20` здоровья, четверть сердца равна `5`.
Когда игрок получает урон, сердечки уменьшаются слева направо.

Картинки сердца лежат тут:

```text
assets/sprites/items/heart.bin
assets/sprites/items/heart_75.bin
assets/sprites/items/heart_50.bin
assets/sprites/items/heart_25.bin
```

Если игрок некоторое время не получает урон, здоровье постепенно
восстанавливается по четверти сердца.

## Что можно менять без прошивки

Можно менять и просто загружать на Pico через `tools/upload_to_pico.py`:

```text
game_core/
api/
backends/
examples/
assets/
```

Нужно заново прошивать `firmware.uf2`, только если менялись файлы:

```text
native_game_module/
```

## Правило для уроков

Дети обычно работают в этих местах:

```text
game_core/world.py    генерация мира
game_core/player.py   движение игрока
game_core/game.py     правила игры и отрисовка
assets/sprites/       картинки
examples/             маленькие учебные игры
```

А эти места лучше считать внутренностями движка:

```text
backends/
native_game_module/
pico/
```

## Пример: поймай подарок

Пример лежит здесь:

```text
examples/catch_gift.py
```

Запуск на компьютере:

```bash
python3 tools/run_catch_gift.py
```

В этой игре нет блоков, земли, травы и камеры.
Она использует тот же API:

```text
Actor
keys.left / keys.right
overlaps()
draw()
```
